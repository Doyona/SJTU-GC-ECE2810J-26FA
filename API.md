# Website data and sync

- `site/data/leaderboard.json`: schemaVersion=2, activeYear, years[]. Each period has id (YYYY-term), year, term, label, organization, archived, demo, updatedAt, and projects. The default cannot be archived. Project and student IDs are scoped to their period.
- `src/manage_years.py list`: list periods and their default/archive status. `add --year YEAR --term fall|spring|summer|winter --organization ORG` creates an empty cohort from existing metric definitions. `set-default ID`, `archive ID`, `unarchive ID`, and `remove-empty ID` manage periods. Populated periods cannot be removed; the default cannot be archived or removed. Commands validate and atomically write the catalog under the synchronization lock, with no Git writes. Use `--website-root PATH` before the command to target a fixture.
- `src/year_catalog.py`: catalog(data) migrates the legacy single-cohort format to 2026-fall without dropping results. find_year, add_year, set_default, archive_year, remove_empty_year and validate implement management invariants.
- `site/leaderboard.mjs`: validateData validates both the current catalog and legacy migration inputs; selectYear resolves a URL ID or activeYear; sortedYears returns newest periods first. Ranking and filtering operate only on a selected period's projects.
- src/sync_task3.py --exporter PATH --env-file PATH [--website-root PATH] [--year-id YYYY-term] [--organization ORG] [--publish]: fetch all visible student Task 3 results; defaults explicitly target 2026-fall/ece281s1. Existing 2026 private state stays under data/task3/; other periods use data/task3/ID/. Update only the target period and the public aggregate (which carries yearId); optionally commit/push the same two JSON files. Changing activeYear does not retarget sync. Archived periods or organization mismatches are rejected. Without --publish there are no Git writes.
- src/sync_task3.py --source-json PATH [--website-root PATH]: offline conversion/verification; cannot be combined with --publish.
- make_snapshot(source): validate complete collection; require release_only collection and choose one best valid p3-release per student: lowest rounds, then lowest movement steps, then earliest result and run ID. A later failed or worse release cannot replace a better result. Emit only 20/20 verified released integer lengths and explicit coverage.
- update_files(root, source, year_id='2026-fall', organization='ece281s1'): validate with the site's actual JavaScript schema before atomic JSON replacement; preserve all other periods and their timestamps; no-op for unchanged results.
- data/task3-leaderboard.json: schemaVersion, organization, caseCount, releaseOnly, referenceOnly, coverage, entries, updatedAt. No token or raw plan content.
- Each period's project-03 uses primaryMetric rounds and secondary movementSteps. The selected period determines displayed timestamps, URL year, and CSV filename.
- LaunchAgent logs: ~/Library/Logs/ece281-task3-sync.stdout.log and .stderr.log. Run launchctl kickstart gui/$(id -u)/com.ece281.task3-sync to refresh manually after installation.
